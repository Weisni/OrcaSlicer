# QuackSlicer 2.5.24

## Behavior

- Derive chamber and first-layer bed targets from the filaments on the submitted
  plate, including support/tool changes. Other plates no longer raise its target.
- Add manual skip to chamber waiting, preserving cancellation and bed restoration.
- Recognize a real lower-temperature plateau using fresh temperature and door
  evidence. A door opening invalidates plateau evidence until recovery and a
  fresh complete window; it does not stop an existing HA heating operation.
- Optionally bind HA preheat to the reserved print attempt. Each request and
  readiness check carries the job/instance identity. Only one owner is admitted
  per printer; there is no queue. Manual advance warming transfers atomically.
- Persist HA ownership across restart and recover zero bed targets reported by
  the idle protection, requiring acknowledgement. Keep idle protection enabled.
- Bypass chamber waiting when the current temperature already meets the target;
  still condition the print bed. Revoke target-only readiness if it falls below
  target before the final dispatch check.
- Allow one additional fifteen-minute stabilization period when fresh safe idle
  data and confirmed heating remain valid. Manual holds and terminal attempts
  are never automatically renewed or revived.
- Recover transient preheat transport failures for at most sixty seconds and
  within the confirmed bounded server deadline. Replay only the same idempotent
  initial preheat request when its result is unknown; never retry a physical
  dispatch or silently switch print paths after an uncertain claim.
- Restore readable HA profile names after importing/reopening embedded profiles,
  preserving saved assignments and local material overrides.
- Restore the send dialog after definitive errors without losing unresolved
  reservation/dispatch bookkeeping.

## Matching Home Assistant integration

The matching integration source is under
`tools/ha-material-demo/demo/custom_components/quack_materials/`.
Back up the installed component and its SQLite database consistently before
updating an existing `quack_materials` installation. Preserve newer local
integration features and configuration; never replace the inventory database.

Both `job_preheat_enabled` and `manual_preheat_enabled` are explicit opt-ins
in the existing `quack_materials` configuration. Do not enable either without
the matching printer assignment, supported Bambu integration/control entities,
fresh raw telemetry and enabled printer idle protection. The server advertises
`job_preheat_v1` only for the enabled job-bound mode. Older integrations retain
the existing slicer preheat path. HA restart must be scheduled outside active
printing and other printer operations; every failed precheck stops installation.

The compact optional `custom:quack-preheat-controls` card takes the physical
`printer_id` and `compact: true`. Start/cancel require an administrator. The card
reads the successor after transfer and displays the reported bed target rather
than presenting the configured warm-up goal as actual printer state. Reload the
dashboard after an integration update to load the current card module.

Cancel a preheat operation to stop HA refreshing its heater target; printer
idle protection handles later shutdown. Do not cancel a transferred manual
predecessor to control the print successor. Resolve uncertain print outcomes
through the existing inventory/provider review instead of resending a job.

The separate test application's copied profile/credential identity and local
project copies are not part of this release. Published builds use the normal
QuackSlicer identity and existing production configuration.

## Validation and remaining acceptance

Local validation includes the complete HA Python suite, HA UI tests, material
contract/import tests, pure preheat protocol/temperature tests, actual client
transport tests and send-dialog finalizer tests. Platform builds and CTest run
through the existing release CI at the reviewed commit.

Software tests and a successful build do not establish printer interoperability
or a completed physical start. No physical heating or print is started as a
release test. Full physical warm-up/takeover/dispatch remains a user acceptance
step. Existing project-local material differences are preserved, not reset.
