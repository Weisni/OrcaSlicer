# QuackSlicer 2.5.19

## Release baseline

The official stable baselines remain OrcaSlicer 2.4.2 and Bambu Studio
2.8.2.61. Their applicable changes were already integrated in earlier
QuackSlicer releases. This maintenance release contains three focused fixes
that were reviewed on the OrcaSlicer development branch and intentionally
deferred from QuackSlicer 2.5.16 to the next update.

## Development-branch audit

The 2026-10-01 audit found no newer official stable OrcaSlicer or Bambu Studio
release to merge. The following development changes look useful but remain out
of this maintenance release pending an explicit decision:

- A focused OrcaSlicer import-security batch covering archive extraction,
  malformed 3MF/OBJ data, untrusted server file names, and project metadata.
- Slicing-correctness fixes for overhang wall slowdown/fan handling,
  inner-outer-inner narrow-wall fallback, sparse wipe-tower layers, and fuzzy
  skin on bridge-like overhangs.
- Larger OrcaSlicer performance and feature work such as parallel preset
  loading, faster G-code export, Precise Seam, X-Ray view, texture displacement,
  and non-crossing infill. These should normally wait for an official release.
- Bambu Studio 2.8.4 beta changes including vase-mode raft Z restoration,
  monotonic top-surface path refinement, texture import improvements, and
  several Device/AMS/text-tool usability changes. These remain beta-only and
  should not be bulk-backported into a maintenance release.

## Safety fixes

- Bound the ASCII STL `solid` name, parse MakerWorld metadata from that bounded
  input, and reject oversized tokens without reassigning their trailing bytes
  to later fields. Valid headers are unchanged; malformed metadata is ignored.
- Hold the existing `SaveObjectGaurd` while CGAL repairs mutate a model object.
  This prevents the backup manager from cloning the same live object from its
  own thread while the repair worker splits, deletes, or replaces volumes.
- Validate and resize per-variant configuration rows before migrating object
  overrides between printers. Short source rows are read only in range, narrow
  destination rows are expanded, and an empty destination variant list is
  rejected.

## Compatibility and side effects

Existing projects, profiles, and inventory databases remain compatible; no
migration is required.

The backup guard is an explicit compromise: intermediate repair mutations are
not queued as separate backups while the worker runs. The completed repair is
queued once when the guard is released on the main thread. This preserves the
final recoverable state without exposing the backup model to concurrent writes.

For per-variant settings, matching values are retained. Missing destination
slots remain nil so they continue to inherit the destination preset rather than
copying a value from an unrelated nozzle variant.

## Validation

- The ASCII STL regression test was observed failing against the initial
  width-limited backport because an oversized model ID was split into the
  country field. It passes after bounded token parsing: 16 assertions in one
  test case, including valid metadata and a full buffer ending in `MW`.
- The per-variant migration regressions pass 24 assertions in two test cases,
  including mismatched rows in all three migration helpers. Width mismatches
  now produce runtime diagnostics instead of Debug-only assertion failures.
- An independent code review identified both edge cases above and confirmed
  the follow-up corrections before the release PR.
- The backup-race change follows the existing `SaveObjectGaurd` lifecycle and
  is covered by the complete Windows build, but it has no deterministic unit
  reproduction. Repeated repair with auto-backup under ASan/TSan remains a
  useful platform-specific stress check.
- The capped-load Windows Release `ALL_BUILD` completed successfully with one
  MSBuild process and at most two compiler workers. CTest passed all 532
  runnable tests; five optional Python host tests were skipped and none failed.
- Static profile validation loaded all 66 vendors successfully. Slice-mode
  validation also sliced all 1,009 printer presets without an error.
- Cross-platform builds and packaging remain the responsibility of the GitHub
  Actions release workflow and must pass before merge and publication.
