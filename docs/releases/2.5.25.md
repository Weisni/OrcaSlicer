# QuackSlicer 2.5.25

Draft release notes. Publication depends on successful validation at the final
reviewed commit.

## Changes

- Integrate the complete official OrcaSlicer 2.5.0 Beta tagged source,
  dependencies, resources and printer profiles. This includes the upstream CAD
  workspace, Python plugins, filament mixing and nozzle variants. Experimental
  labels and device restrictions remain in effect.
- Preserve Quack physical-roll UUIDs, stock and reservations, customer/order
  history, HA profile authority, job-bound preheat and signed-update behavior.
  No custom feature is retired in favor of an unverified upstream equivalent.
- Accept existing HA material profiles through the bounded schema migration,
  preserve their saved identity on reload and keep unknown consumption unknown
  during inventory import.
- Keep HA roll bindings, local edits and readable names across native nozzle/
  flow changes and restarts. Normalize credential lookup across equivalent
  data paths without importing another application's credentials.
- Preserve virtual mixture components and proportions when retaining project
  settings during a nozzle change. Keep virtual slots separate from physical
  roll bindings and preserve selected physical-roll assignments and material colors.
  Object menus identify a virtual material as a mixed filament.
- Correct uncovered Wave Overhang support islands while preserving ordinary
  support behavior when the optional wave path is disabled.
- Require an explicit tracking opt-out before native multi-printer export.
  Cancel is the default: untracked sends do not reserve/deduct stock, associate
  customer orders or record inventory costs. Preserve parallel native sends
  after that decision. HA material modes and passive chamber preheating require
  the protected single-printer path; pending jobs recheck these modes and their
  stored approval immediately before dispatch.
- Keep Python plugins outside authoritative filament inventory storage,
  including database sidecars and backups.
- Separate Quack Flatpak/D-Bus and macOS application identities from official
  OrcaSlicer. Keep local Beta Test credentials and updates isolated from the
  production application.
- Require the complete hosted platform asset matrix, exact source/tag version,
  HA regression gate and verified SHA-256 digests before release publication.
  Publish 2.5.25 on the regular release channel, as selected by the maintainer.
  Its upstream source basis is OrcaSlicer 2.5.0 Beta.

## Validation and remaining acceptance

Local Windows native tests, targeted HA/material regressions and isolated GUI
checks are recorded in the integration acceptance reports. Release-pipeline
fixture tests, workflow linting and metadata syntax checks also ran locally.
These results do not establish complete upstream feature parity.

Full Windows x64/arm64, macOS universal and Linux x86_64/aarch64 hosted CI,
Flatpak packaging and final package verification remain pending at the final
reviewed commit. Self-hosted builds omit supported lanes and cannot qualify a
complete release. The local build-script suite also requires Clang components
that are absent on the current PC; no compiler was installed to mask that gap.

Cross-platform runtime coexistence, external cloud/plugin services and physical
printer acceptance remain separate checks. No production HA deployment,
heating or physical print is performed as release validation. Existing project,
profile and accounting data must remain recoverable throughout migration.

The macOS delivery image stages `QuackSlicer.app` separately from official
`OrcaSlicer.app`; internal build-tree names remain unchanged. Published Linux
artifacts use AppImage or sandboxed Flatpak. Unsandboxed native FHS source
installations still share executable/resource paths with upstream OrcaSlicer
and are not supported as a side-by-side installation in the same prefix.
